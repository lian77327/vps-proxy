VPS для прокси: как выбрать сервер и поднять свой прокси за час

Покупать готовые прокси по подписке в 2026-м - значит платить за чужой засвеченный IP, делить полосу с парсерами соседа и молиться, что провайдер не сольёт логи. Свой прокси-сервер на VPS решает все три проблемы разом. И стоит дешевле, чем кофе в Шоколаднице.

В этом гайде разбираю, какой VPS для прокси реально брать под разные задачи, какие провайдеры не врут про канал, как за двадцать минут поднять SOCKS5 через 3proxy и MTProto для Telegram. Без воды. С конфигами, ценами и моими косяками по ходу настройки.

Я держу собственные прокси на VPS с 2019-го. Сначала для парсинга маркетплейсов, потом под антидетект-браузеры, сейчас - в основном для команды и личного VPN-стека. За эти годы перепробовал десяток хостеров, словил три блокировки IP подряд от РКН и научился ставить 3proxy с закрытыми глазами. Поехали.

Что внутри статьи: требования к серверу под VPS прокси, рейтинг 8 хостеров с честными ценами, пошаговая установка прокси на VPS (3proxy, Squid, MTProto, Xray), reverse proxy на VPS через Nginx, защита и аутентификация. Внешние источники: официальная документация 3proxy, репозиторий MTProxy, RFC 7858 про DNS-leak.

Зачем нужен свой прокси-сервер на VPS

Готовый прокси за 30 рублей в месяц - это IP, через который до вас прошло уже тысяч пять любителей грязного скрейпинга. Его уже забанили в Google, Cloudflare пометил как datacenter, Instagram кидает на чек при первом запросе. Свой прокси на VPS даёт чистый IP, который видит только вы.

Дальше - приватность. У продавцов готовых прокси логи лежат вечно, и при первом запросе от условного Роскомнадзора утекают целиком. На своём VPS вы сами решаете, писать ли логи и куда. Я обычно отключаю их полностью в /etc/3proxy/3proxy.cfg строкой nolog.

Цена. Готовый residential за 5 баксов в месяц даёт 1 ГБ трафика. VPS для прокси за те же 5 евро у Hetzner или Contabo - 20 терабайт. Разница в двадцать тысяч раз, если кто не считал.

Контроль. На VPS вы крутите столько прокси, сколько влезет в RAM. Один сервер с 2 ГБ оперативки спокойно держит 5-7 портов: SOCKS5, HTTP, HTTPS, MTProto - всё одновременно. Поменяли пароль - переподключились. Залочили доступ по белому списку IP - спите спокойно.

Ну и обход блокировок. На фоне апрельского угара 2026-го с ТСПУ и законопроектом «Антифрод 2.0» (его «Коммерсантъ» разобрал в апреле) свой прокси - не игрушка, а базовая инфраструктура. Российским хостерам собираются прямо запретить размещать VPN-сервисы. К прокси формально это не относится, но я бы давно перенёс всё в Европу.

Что не закрывает свой VPS? Геотаргетинг под «нужен IP из штата Огайо». Если задача - именно residential-пул, идите в Bright Data или Smartproxy. Для всего остального хватает datacenter IP на собственном сервере.

Какой VPS выбрать для прокси

Прокси - не PostgreSQL под нагрузкой и не Stable Diffusion. Ресурсов жрёт мало, требований к диску почти нет. Но есть нюансы, на которых начинающие админы садятся в лужу.

Процессор и RAM

Для SOCKS5 и HTTP на 3proxy хватает 1 vCPU и 512 МБ оперативки. Я гонял такой стек на самом дешёвом тарифе Beget за 210 рублей - держит до 50 одновременных соединений без чиха. Для MTProxy на канал с тысячей подписчиков - тоже 1 vCPU и 1 ГБ. Для Xray с VLESS+XHTTP уже желателен 1 ГБ RAM минимум, лучше 2.

Канал

Вот тут косячат все. Многие хостеры пишут «порт 1 Гбит/с», а в правилах мелким шрифтом - shared, fair use, до 100 Мбит/с гарантированно. Под прокси это критично: если через сервер льётся 4К-видео или парсер качает картинки, узкий канал убьёт всё. Я гоняю iperf3 сразу после оплаты, до того как накатывать что-то серьёзное. У AdminVPS на финской площадке честные 800-900 Мбит/с в пике, у Aeza во Франкфурте видел 1.2 Гбит/с по факту. Hetzner - честный гигабит без оговорок.

IP-адреса

Один IPv4 в стандарте есть везде. Если нужны несколько IP под мультиаккаунты или антидетект - смотрите в сторону провайдеров с возможностью докупки. У Hostkey доп IP стоит около 170 рублей, у Aeza - €2/мес. /29 подсеть (8 адресов, из которых полезных 5) дают единицы, обычно по запросу в саппорт. IPv6 раздают почти все, но половина сервисов в интернете на него до сих пор не умеет.

Локация

Под Telegram и обход блокировок - Нидерланды и Финляндия. Амстердам быстрый, пинг из Москвы 35-40 мс. Хельсинки - 15-25 мс из Питера, рекорд по близости. Под парсинг западных площадок - Германия (Франкфурт, AMS-IX и DE-CIX рядом, маршруты короткие). США берите, только если действительно нужен американский IP - пинг 100-150 мс, под Telegram некомфортно.

Виртуализация

Только KVM. OpenVZ - в утиль, на нём не поставите кастомное ядро, нормальный iptables и половину современного софта. Все нормальные провайдеры давно ушли с OVZ. Если в тарифе вижу OpenVZ - закрываю вкладку.

ОС

Прокси-сервер Ubuntu VPS - очевидный выбор. Ubuntu 22.04 LTS или 24.04 LTS. Debian 12 - тоже отлично, мне даже больше нравится за отсутствие snap-овой возни. CentOS Stream - если у вас уже есть инфраструктура на RHEL. Прокси на VPS с Windows - отдельная тема ниже, обычно её не хотят, но иногда приходится.

Как поднять прокси-сервер на VPS: пошаговая инструкция

Дальше - руками. Все команды проверял на свежей Ubuntu 22.04 LTS, на других дистрибутивах меняются только пакетные менеджеры.

Подключение по SSH

Берёте IP и root-пароль из письма хостера, открываете терминал:

ssh root@ВАШ_IP

Сразу обновляем систему и ставим базовые утилиты:

apt update && apt upgrade -y apt install -y wget curl ufw build-essential

SOCKS5 прокси на VPS через 3proxy

3proxy - швейцарский нож. SOCKS4, SOCKS5, HTTP, HTTPS, FTP - всё в одном бинарнике, конфиг на 20 строк. Жрёт меньше 10 МБ оперативки. Под установку прокси на VPS - выбор номер один. В репозиториях Ubuntu свежей версии нет, собираем из исходников:

cd /opt wget https://github.com/3proxy/3proxy/archive/refs/tags/0.9.4.tar.gz tar xzf 0.9.4.tar.gz cd 3proxy-0.9.4 make -f Makefile.Linux make -f Makefile.Linux install

Создаём конфиг /etc/3proxy/3proxy.cfg:

daemon nserver 1.1.1.1 nserver 8.8.8.8 nscache 65536 timeouts 1 5 30 60 180 1800 15 60 log /var/log/3proxy/3proxy.log D rotate 7 users myuser:CL:МойПарольПосложнее auth strong allow myuser socks -p1080 proxy -p3128 flush

Тут: users - имя и пароль (CL = cleartext, для прода замените на CR с MD5-хэшем), auth strong - требовать авторизацию, socks -p1080 - SOCKS5 на порту 1080, proxy -p3128 - HTTP на 3128.

Systemd-юнит для автозапуска /etc/systemd/system/3proxy.service:

[Unit] Description=3proxy Proxy Server After=network.target [Service] Type=forking ExecStart=/usr/local/bin/3proxy /etc/3proxy/3proxy.cfg Restart=on-failure [Install] WantedBy=multi-user.target

Запускаем:

systemctl daemon-reload systemctl enable --now 3proxy systemctl status 3proxy

Открываем порты в файрволе:

ufw allow 22/tcp ufw allow 1080/tcp ufw allow 3128/tcp ufw enable

Проверяем с локальной машины:

curl -x socks5://myuser:МойПарольПосложнее@ВАШ_IP:1080 https://api.ipify.org

Должен вернуться IP вашего VPS. Если вернулся - вы только что подняли свой SOCKS5 прокси на VPS. Поздравляю. Если нет - смотрите journalctl -u 3proxy -f и не забудьте проверить, что хостер не режет исходящие порты (бывает у Hostkey на дефолтных тарифах).

HTTP/HTTPS прокси через Squid

Squid - монстр на 30+ МБ оперативки и тонны опций. Кэширование, ACL, аутентификация через LDAP - всё есть. Но я его ставлю только когда нужно именно кэширование (корпоративный шлюз, экономия трафика). Для чистого HTTP-прокси - оверкилл.

apt install -y squid apache2-utils htpasswd -c /etc/squid/passwd myuser

В /etc/squid/squid.conf находим блок ACL и добавляем:

auth_param basic program /usr/lib/squid/basic_ncsa_auth /etc/squid/passwd auth_param basic realm proxy acl authenticated proxy_auth REQUIRED http_access allow authenticated http_access deny all http_port 3128

Рестарт: systemctl restart squid. Логи: /var/log/squid/access.log. Документация - на squid-cache.org.

Защита: белый список IP вместо пароля

Если прокси нужен только вам и команде, забейте на логин-пароль и пустите по IP. В 3proxy:

allow * 95.123.45.67,178.234.56.78 deny * socks -p1080

В iptables/ufw - то же самое:

ufw allow from 95.123.45.67 to any port 1080 ufw allow from 178.234.56.78 to any port 1080 ufw deny 1080

Так создать прокси-сервер на VPS гораздо безопаснее, чем светить логин-пароль в каждом скрипте.

Несколько прокси на одном сервере

Поднимаем 3proxy с десятком портов:

socks -p1080 socks -p1081 socks -p1082 proxy -p3128 proxy -p3129

Каждый порт - отдельный «прокси» для распределения по аккаунтам/задачам. На VPS с 1 ГБ RAM спокойно живут 10+ портов одновременно. Подробности конфигурации - в официальной документации 3proxy.

Альтернативы 3proxy: Dante (классический SOCKS5-сервер, чуть жирнее), Tinyproxy (простейший HTTP-прокси), Privoxy (HTTP с фильтрацией рекламы), Shadowsocks-libev (когда нужна обфускация), HAProxy (балансировка нагрузки), Sing-box (универсальный современный комбайн).

MTProto-прокси для Telegram на VPS

Отдельная история. Хостинг для прокси тг - это вообще не SOCKS, и универсальные решения сюда не подходят. MTProto - официальный протокол Telegram, его сигнатура замаскирована под белый шум TLS, ТСПУ его пока не научились ловить надёжно (тьфу-тьфу).

Ставим официальный mtproto-proxy от Telegram. Способ номер раз - скрипт от HirbodBehnam, проверенный временем:

curl -L -o MTProtoProxyInstall.sh https://git.io/fjo34 bash MTProtoProxyInstall.sh

Скрипт спросит порт (по умолчанию 443 - маскируется под HTTPS, не выбирайте 8443 и подобные «прокси-порты», их режут), сгенерирует secret и выдаст готовую ссылку вида tg://proxy?server=...&port=...&secret=....

Способ номер два, руками. Клонируем официальный репозиторий MTProxy, собираем:

git clone https://github.com/TelegramMessenger/MTProxy cd MTProxy make cd objs/bin curl -s https://core.telegram.org/getProxySecret -o proxy-secret curl -s https://core.telegram.org/getProxyConfig -o proxy-multi.conf head -c 16 /dev/urandom | xxd -ps

Последняя команда выдаст ваш secret. Запуск:

./mtproto-proxy -u nobody -p 8888 -H 443 -S ВАШSECRET \ --aes-pwd proxy-secret proxy-multi.conf -M 1

Привязка к каналу - через -T ТЕГ_КАНАЛА после получения тега от @MTProxybot. За промо в виде спонсорского сообщения от вашего канала на закрепе у пользователей прокси - вполне честный обмен.

Systemd-юнит обязателен, иначе при перезагрузке VPS прокси для Telegram на VPS упадёт молча и навсегда.

Важное про MTProto на VPS в России. На Habr недавно вышел пост с комментарием: «mtproto на российском VPS убит РКН примерно за день, никакой туннель дальше не спасёт». Подтверждаю на личном опыте. На российских площадках MTProxy на VPS живёт от нескольких часов до пары дней - потом IP в блокировке. Берите европейские локации: Финляндия (AdminVPS, Aeza), Нидерланды (Fornex, Hostkey), Германия. Из СПб финский MTProxy даёт 15-20 мс задержки, разницы с локальным каналом не заметите.

Альтернативы MTProxy

Если MTProxy надоел - смотрите Xray с VLESS+XHTTP (новый транспорт, маскируется под HTTPS, ТСПУ пока не ловят), V2Ray, Sing-box. VLESS+XHTTP стал рабочей альтернативой VLESS Reality после того, как РКН научился ловить последний по паттерну TLS-хендшейков (разбор был на Habr в феврале 2026-го). Под Xray на VPS закладывайте минимум 1 ГБ RAM, в идеале 2.

Reverse proxy на VPS: бонусный сценарий

Reverse proxy - это когда сервер стоит перед вашим веб-приложением, принимает запросы извне и проксирует их вглубь. Классика - Nginx reverse proxy для HTTPS-терминации и балансировки.

Минимальный конфиг Nginx:

server { listen 443 ssl http2; server_name api.example.com; ssl_certificate /etc/letsencrypt/live/api.example.com/fullchain.pem; ssl_certificate_key /etc/letsencrypt/live/api.example.com/privkey.pem; location / { proxy_pass http://127.0.0.1:8080; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for; } }

SSL через certbot --nginx. Время разворачивания - минут 10. Под reverse proxy на VPS подойдёт буквально любой тариф с 1 ГБ RAM. Документация - nginx.org.

Прокси на VPS с Windows

Иногда нужен. Например, под специфический софт, который ходит только через системные настройки Windows-прокси, или под антидетект-браузеры, требующие именно винду на стороне сервера. Сценарий редкий, но рабочий. AdminVPS, Hostkey и Timeweb Cloud дают Windows Server 2019/2022 в шаблонах. Лицензия обычно стоит +200-400 ₽/мес сверху.

Под Windows ставится CCProxy (платный, но удобный), WinGate или 3proxy под Windows (есть скомпилированная версия). 3proxy для Windows я гонял - работает, конфиг тот же, что в Linux, кладётся рядом с экзешником. Сервис ставится одной командой 3proxy.exe --install.

Минус Windows-сценария - оверхед по RAM (минимум 2 ГБ против 512 МБ на Linux) и более высокий ценник. Если можете жить на Linux - живите.

Безопасность и анонимность прокси на VPS

Прокси без защиты - это IP, который через неделю утечёт в публичные списки и через две будет банить сам себя.

Аутентификация

Минимум - логин-пароль. Лучше - белый список IP. Идеально - и то, и другое.

SSH-ключи вместо пароля root

Сразу после первого входа:

ssh-copy-id root@ВАШ_IP # на сервере: nano /etc/ssh/sshd_config # PasswordAuthentication no # PermitRootLogin prohibit-password systemctl restart sshd

Файрвол

UFW или iptables - закрываем всё, кроме SSH и портов прокси:

ufw default deny incoming ufw default allow outgoing ufw allow 22/tcp ufw allow 1080/tcp ufw enable

Fail2ban

Обязательно. Защищает от брутфорса SSH и портов прокси:

apt install -y fail2ban systemctl enable --now fail2ban

Логи

Включайте только если они нужны для дебага. По умолчанию - nolog в 3proxy, минимальный access_log в Squid. Логи юзер-агентов и URL клиентов хранить в 2026-м - себе дороже. Заодно подумайте про логротейт, иначе диск забьётся за месяц.

Защита от утечек DNS

В 3proxy укажите nserver с DoH/DoT-резолверами или внешними (1.1.1.1, 8.8.8.8), чтобы DNS-запросы клиента не уходили через провайдера. Подробнее про DNS-leak - в RFC 7858.

Регулярные обновления

apt update && apt upgrade -y раз в неделю, через cron или unattended-upgrades.

И ещё один совет от практика: не используйте порт 1080 на проде - его сканируют автоматически тысячи ботов в минуту. Переезжайте на нестандартный высокий порт типа 47821. Это не безопасность, но шума в логах меньше на порядок.

Под какие задачи берут VPS прокси

Самые частые сценарии из практики, с привязкой к конфигурациям.

Обход блокировок и личный VPN-стек

1 vCPU, 512 МБ - 1 ГБ RAM, 10-15 ГБ диска. Подойдёт любой минимальный тариф из подборки. AdminVPS Финляндия с промо VPS30 - топовый выбор по соотношению цена/пинг.

Парсинг сайтов и web scraping

2 vCPU, 2-4 ГБ RAM, обязательно гигабит. Хостер не должен резать исходящие соединения. Hetzner CX22, Aeza, Hostkey - проверены. На один VPS вешаете 5-10 SOCKS5-портов через 3proxy и распределяете между потоками краулера.

Мультиаккаунты и антидетект-браузеры

Под Dolphin{anty}, AdsPower, Multilogin, GoLogin - нужны разные IP под каждый профиль. Берите VPS с возможностью докупки доп IP: Hostkey (170 ₽/мес за IP), Aeza (€2/мес), или /29 подсеть за 500-700 ₽. На один IP - один профиль антидетекта, иначе смысл теряется.

Арбитраж трафика и SMM

Сценарий близок к мультиаккаунтам: нужны гео-IP под рекламные сети, тестирование креативов с разных регионов, заходы в соцсети из нужной страны. Aeza с её семью странами ЕС - тут вне конкуренции.

Корпоративный шлюз

20+ сотрудников через один прокси-сервер - 4 vCPU, 4-8 ГБ RAM, гигабит, безлимит трафика. Squid с кэшированием экономит трафик на 30-40% для офиса. Timeweb Cloud с документами для юрлица - идеально под такой кейс.

Telegram через прокси

MTProxy на минимальной конфигурации (1 vCPU, 1 ГБ). На канал до 10 000 пользователей хватает. AdminVPS Финляндия или Aeza Хельсинки - пинг минимальный, протокол летит. Бонус - можно привязать канал и собирать трафик в свою аудиторию.

Часто задаваемые вопросы про VPS для прокси

Самое практичное из того, что спрашивают в саппорте и комментариях

Можно ли поднять прокси на бесплатном хостинге?
Технически - на Oracle Cloud Free Tier (1 vCPU, 1 ГБ RAM, навсегда) можно поставить 3proxy и крутить личный SOCKS5. Практически - аккаунты Oracle постоянно банят за «подозрительную активность», особенно после регистрации с российского IP. Бесплатный хостинг для прокси-сервера на VPS существует, но это лотерея с месячным сроком жизни. Для стабильности - платный VPS от 200 рублей. Дешевле, чем нервы.
Сколько прокси можно сделать на одном VPS?
На тарифе с 1 ГБ RAM - до 20 одновременных портов 3proxy с лёгкой нагрузкой. На 2 ГБ - 50+. Узкое место не процессор и не память, а канал и количество одновременных соединений. Один порт SOCKS5 на 3proxy спокойно держит 100-200 коннектов. То есть VPS прокси за 500 рублей закрывает потребности команды из 10 человек без напрягов.
Какой VPS дешевле для прокси?
В рублёвой зоне - Beget (210 ₽) и VDSina (240 ₽), оба в Нидерландах. В зарубежной - Hetzner CX22 за €4.99 с 4 ГБ RAM (но российские карты не принимает). Дешёвый VPS для прокси на 1-2 пользователя - FirstByte от 259 ₽, проверено лично.
Как сделать несколько прокси на одном сервере?
Открываете в /etc/3proxy/3proxy.cfg десяток строк socks -pПОРТ или proxy -pПОРТ - каждая создаёт отдельный прокси на своём порту. Можно прописать разные users для разных портов через auth strong и allow ИМЯ. Подробности - в официальной документации 3proxy на 3proxy.org.
Нужны ли дополнительные IP-адреса?
Под обход блокировок одного IPv4 хватает. Под мультиаккаунты и антидетект (Dolphin, AdsPower, Multilogin) - чем больше, тем лучше. Один IP = один «чистый» аккаунт без следов. Доп IP стоит от 100 до 300 ₽/мес. /29 подсеть (5 полезных IP) - от 500 ₽. У Hostkey - 170 ₽, у Aeza - €2.
Легально ли держать свой прокси на VPS?
В России - юридически серая зона. Закон о VPN-сервисах (ФЗ-276) распространяется на сервисы, обеспечивающие доступ к заблокированным ресурсам. Личный прокси для собственного использования прямо не запрещён, но и не легализован. Законопроект «Антифрод 2.0» апреля 2026-го планирует прижать российских хостеров за размещение «средств обхода блокировок». Поэтому хостинг для прокси и VPN - однозначно в Европу. В большинстве европейских стран свой прокси - абсолютно легально, это просто сетевой сервис.
Чем отличается прокси-хостинг от обычного VPS?
Ничем технически. «Прокси-хостинг» - маркетинговое название VPS, заточенного под прокси: гигабитный порт, безлимит/много трафика, чистый IP без истории жалоб. Берите обычный VPS у адекватного провайдера - получите тот же результат за меньшие деньги.
VPS через прокси - это как?
Обратный сценарий: вы ходите на свой VPS через внешний прокси. Зачем - когда ваш домашний IP заблокирован на сервере или когда хостер режет соединения из определённых стран. SSH через прокси настраивается в ~/.ssh/config через ProxyCommand с nc -X 5 -x ПРОКСИ:1080. Редкий, но иногда нужный кейс.
Прокси-сервер Ubuntu VPS или Debian - что лучше?
Ubuntu 22.04/24.04 LTS - стандарт индустрии, документации больше. Debian 12 - чище, без snap-овой возни, минимально пакетов в базе. Под 3proxy и Squid разницы вы не увидите. Я лично предпочитаю Debian для прокси-нод, потому что меньше «лишних» сервисов из коробки = меньше векторов атаки.
Можно ли поставить Windows на VPS под прокси?
Можно, но смысла мало. Прокси на VPS Windows нужен только когда специфический софт ходит через системные настройки винды или антидетект-браузер требует Windows на сервере. Минимум 2 ГБ RAM (против 512 МБ на Linux), лицензия +200-400 ₽/мес. AdminVPS, Hostkey, Timeweb Cloud дают шаблоны Windows Server 2019/2022.
Какой VPS Финляндия взять под MTProto?
AdminVPS Финляндия с промокодом VPS30 - пинг 15-20 мс из СПб, MTProxy работает идеально. Или Aeza Хельсинки на Ryzen 9 - почасовая оплата, можно тестировать без обязательств. Хостинг для прокси тг в Финляндии - один из лучших по соотношению пинг/цена для русскоязычной аудитории.
Что делать, если IP моего прокси попал в чёрный список?
У Aeza и Timeweb Cloud переключение IP - бесплатно по тикету. У Hetzner - €1 за смену. У AdminVPS - по запросу в саппорт. Перед заказом тарифа проверьте IP через mxtoolbox.com - иногда хостеры выдают «грязные» адреса с историей рассылок. Если IP сразу в спам-листах - возврат денег по money-back, никто не упрётся.
